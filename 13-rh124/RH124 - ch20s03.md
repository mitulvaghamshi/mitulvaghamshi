**Specifications**\
You have moved into the next stage of the systemd administrator internship where you are asked to do some administrative tasks. In your new project, database users have access to a specific location to create, edit, and store database files. To allow these database users to manage files collaboratively, you must modify permissions so that all users have access to all files that are created in this location. The other restriction to consider is that only owners of the files can delete them.\
Perform the following tasks on the serverb machine:

- Identify and terminate the process that currently uses the most CPU time.
- Create the database group with a group ID (GID) of 50000.
- Create the dbadmin1 user and configure it with the following requirements:
  - Add the database group as a supplementary group.
  - Set the password to redhat and force a password change on first login.
  - Allow the password to be changed 10 days after the last password change.
  - Configure the password to expire 30 days after the last password change.
  - Allow the user to use Sudo to run any command as the superuser by creating its own sudoers file.
  - Configure the default umask as 007 for the dbadmin1 user.
-
- Create the /home/dbadmin1/review2 directory and configure it to ease group collaboration with the following requirements:
  - The directory should be owned by the dbadmin1 user and the database group.
  - Members of the database group must have full access to create content in the directory but ensure that they are allowed to delete only files that they own.
  - Any new files or subdirectories created in the /home/dbadmin1/review2 directory must automatically inherit the database group as their owner, regardless of which user creates them.
  - All other users on the system should be allowed to view the /home/dbadmin1/review2 directory, and navigate into it, but not modify its contents.
  - Configure the /home/dbadmin1 directory to permit access to the /home/dbadmin1/review2 directory without allowing other users to list the entire contents of the /home/dbadmin1 directory.
-

1. Log in to the serverb machine as the student user.
2. Identify and terminate the dd process that currently uses the most CPU resources.
3. Switch to the root user, and create the dbadmin1 user based on the requirements.
   1. Create the database group with a group ID (GID) of 50000.[student@serverb ~]$ **sudo -i**
   2. [sudo] password for student: **student**
   3. [root@serverb ~]# **groupadd -g 50000 database**
   4. Create the dbadmin1 user as a member of the database supplementary group.[root@serverb ~]# **useradd -G database dbadmin1**
   5. Set the password expiration policy for the user.[root@serverb ~]# **chage -d 0 -m 10 -M 30 dbadmin1**
4. Update the dbadmin1 user password to redhat.
5. Create the /etc/sudoers.d/dbadmin1 file with the following content:dbadmin1 ALL=(ALL) ALL
6. Switch to the dbadmin1 user. Append the umask 007 line to the /home/dbadmin1/.bashrc file.[root@serverb ~]# **su - dbadmin1**
7. [dbadmin1@serverb ~]$ **echo "umask 007" >> .bashrc**
8. [dbadmin1@serverb ~]$ **source ~/.bashrc**
9. Create the /home/dbadmin1/review2 directory and configure it to ease group collaboration.
   1. Create the directory using the mkdir command. Then view the directory entry to verify its default permissions.[dbadmin1@serverb ~]$ **mkdir review2**
   2. [dbadmin1@serverb ~]$ **ls -ld review2**
   3. drwxrwx---. 2 dbadmin1 dbadmin1 6 Aug 15 15:56 review2
   4. The directory should be owned by the dbadmin1 user and the database group. Adjust the ownership of the directory using the chown command.[dbadmin1@serverb ~]$ **chown :database review2**
10. Members of the database group must have full access to create content in the directory but ensure that they are allowed to delete only files that they own.
    1. The default umask for this user ensures full group access to content created by this user. However, in the absence of the appropriate umask setting, the chmod command can be used to make the adjustment manually.[dbadmin1@serverb ~]$ **chmod g=rwx review2**
    2. Using the chmod command, set the sticky bit permission on the directory to ensure that users are allowed to delete only their own files.[dbadmin1@serverb ~]$ **chmod o+t review2**
11. Any new files or subdirectories created in the /home/dbadmin1/review2 directory must automatically inherit the database group as their owner, regardless of which user creates them. Use the chmod command to configure the setgid permission bit on the directory.[dbadmin1@serverb ~]$ **chmod g+s review2**
12. All other users on the system should be allowed to view the /home/dbadmin1/review2 directory, and navigate into it, but not modify its contents. Use the chmod command to make the directory readonly for users that are not members of the database group.[dbadmin1@serverb ~]$ **chmod o+rx review2**
13. View the /home/dbadmin1/review2 directory entry to verify that its permissions are correct.[dbadmin1@serverb ~]$ **ls -ld review2**
14. drwxrwsr-t. 2 dbadmin1 database 28 Aug 15 16:15 review2
15. Configure the /home/dbadmin1 directory to permit access to the /home/dbadmin1/review2 directory without allowing other users to list the entire contents of the /home/dbadmin1 directory.
    1. Use the chmod command to provide execute permission to others on the directory.[dbadmin1@serverb ~]$ **chmod o+x /home/dbadmin1**
    2. View the directory entry to verify that its permissions are correct.[dbadmin1@serverb ~]$ **ls -ld /home/dbadmin1**
    3. drwx-----x. 3 dbadmin1 dbadmin1 98 Aug 12 21:13 /home/dbadmin1
16. After completing the tasks of this activity, return to the workstation machine as the student user.

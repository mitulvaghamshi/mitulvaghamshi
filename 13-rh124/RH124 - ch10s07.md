# Managing Local Group Accounts

## Objectives

- Create, modify, and delete local group accounts.

## Managing Local Groups

You can manage groups by using the Accounts menu in the RHEL web console (if enabled) or by using command-line tools. This section focuses on command-line tools that you can use from a shell prompt, either locally, over an SSH connection, or in the RHEL web console.\
**Creating Groups from the Command Line**\
The groupadd command creates groups. Without options, the groupadd command uses the next available group ID (GID) number from the range that the GID_MIN and GID_MAX variables specify in the /etc/login.defs file. By default, the command assigns a GID value that is greater than any other existing GIDs, even if a lower value becomes available.\
The groupadd command -g option specifies a GID for the group to use.\
The groupadd command -g option specifies a GID for the group to use.

```
root@host:~# groupadd -g 10000 group01
root@host:~# tail /etc/group
...output omitted...
group01:x:10000:
```

## Note

Because the useradd command automatically creates user private groups with GID numbers assigned from 1000 and up, some administrators set aside a special range of high GID numbers to use when they create supplementary groups for other purposes. However, this extra management is unnecessary, because a user's UID and primary GID do not need to be the same number.\
The groupadd command -r option creates system groups. As with regular groups, system groups use a GID from the range of listed valid system GIDs in the /etc/login.defs file. The SYS_GID_MIN and SYS_GID_MAX configuration items in the /etc/login.defs file define the range of system GIDs.\
The groupadd command -r option creates system groups. As with regular groups, system groups use a GID from the range of listed valid system GIDs in the /etc/login.defs file. The SYS_GID_MIN and SYS_GID_MAX configuration items in the /etc/login.defs file define the range of system GIDs.

```
root@host:~# groupadd -r group02
root@host:~#
```

```
tail /etc/group
```

```
...output omitted...
group01:x:10000:
group02:x:988:
```

**Modifying Existing Groups from the Command Line**\
The groupmod command changes the properties of an existing group. The groupmod command -n option specifies a new name for the group.\
The groupmod command changes the properties of an existing group. The groupmod command -n option specifies a new name for the group.

```
root@host:~# groupmod -n group0022 group02
root@host:~# tail /etc/group
...output omitted...
group0022:x:988:
```

Notice that the group name updates from group02 to group0022.\
The groupmod command -g option reassigns the group name to a new GID.

```
root@host:~# groupmod -g 20000 group0022
root@host:~# tail /etc/group
...output omitted...
group0022:x:20000:
```

Notice that the GID changes from 988 to 20000.\
**Deleting Groups from the Command Line**\
The groupdel command removes groups.

```
root@host:~# groupdel group0022
```

## Important

You cannot remove a group if it is the default primary group of an existing user. Similar to using the userdel command, ensure that you first locate files that the group owns to prevent potential security risks.\
**Primary and Supplementary Group Membership**\
A user's default primary group is the group that is listed on the line that defines the user's account in the /etc/passwd file. A user can belong to only one primary group at a time.\
A user's supplementary groups are the additional groups that are configured for the user in the /etc/group file. A user can belong to many supplementary groups.\
For configuring group-based file permissions, no difference exists between a user's primary and supplementary groups. If the user belongs to any group that is assigned access to specific files, then that user has access to those files.\
The only distinction between a user's primary and supplementary memberships is when a user creates a file. New files must have a user owner and a group owner, which is assigned when the file is created. The user's current primary group is used for the new file's group ownership, unless command options override it.\
**Changing Group Membership from the Command Line**\
Use the usermod -g command to change a user's default primary group.\
Use the usermod -g command to change a user's default primary group.

```
root@host:~# id user02
uid=1006(user02) gid=1008(user02) groups=1008(user02)
root@host:~#
```

```
usermod -g group01 user02
```

```
root@host:~# id user02
uid=1006(user02) gid=10000(group01) groups=10000(group01)
```

## Important

Using the -g option to change a user's default primary group does not automatically add the old primary group to the user's list of supplementary groups. You can see this behavior in the preceding example.\
In addition, using this option does not change group ownership of any existing files in the user's home directory or elsewhere on the system.\
Use the groupmod -aU command to add a list of one or more users to a supplementary group. The name of the group is the final argument to the command.

```
root@host:~# id user03
uid=1007(user03) gid=1009(user03) groups=1009(user03)
root@host:~# groupmod -aU user03 group01
root@host:~#
```

```
id user03
```

```
uid=1007(user03) gid=1009(user03) groups=1009(user03),10000(group01)
```

## Warning

The groupmod command -a option enables append mode. Without the -a option, the command replaces the existing set of users that are members of the group with those that are included in the -U option's list.\
You can also use usermod -aG command to add a user to one or more existing groups without removing them from their current primary or secondary groups. The -a option appends the user to the new group without removing them from the existing group. The -G option specifies a list of supplementary groups to which the user should be added.

```
root@host:~# usermod -aG group01 user03
```

**Temporarily Changing Your Primary Group**\
A user's current primary group determines the group that owns newly created files.\
However, you can temporarily switch your current primary group to one of the supplementary groups to which you belong. You might do this immediately before creating a set of files that you want that group to own, instead of your usual primary group.\
Use the newgrp command to switch your primary group for the current shell prompt. This temporary change does not affect other shell prompts on the same system.\
You can switch your current primary group to any of the supplementary groups that you belong to, or back to your default primary group. Only one group at a time can be your current primary group. If you log out and log back in, then your default primary group at that shell prompt will be the current one again.\
In this example, the group01 group temporarily becomes this user's primary group.\
In this example, the group01 group temporarily becomes this user's primary group.

```
user03@host:~$ id
uid=1007(user03) gid=1009(user03) groups=1009(user03),10000(group01)
user03@host:~$ newgrp group01
user03@host:~$
```

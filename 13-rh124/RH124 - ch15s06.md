## Guided Exercise: Send Signals to Processes

Send signals to processes to control their activity or to terminate execution.\
**Outcomes**

- Start and stop multiple shell processes.\
  As the student user on the workstation machine, run the following lab command to prepare your environment for this exercise, and to ensure that all required resources are available.

```
student@workstation:~$ lab start processes-kill
```

**Instructions**

1. On the workstation machine, open two terminal windows side by side. In this activity, these terminals are referred to as left and right. In each terminal, log in to the servera machine as the student user.student@workstation:~$ **ssh student@servera**
2. [student@servera ~]$
3. In the left terminal shell, start three processes in the background with the instance script file, by passing the network, interface, and connection arguments.The instance script appends command-line arguments to the ~/instance_outfile file once per second. The script runs until the process is terminated.[student@servera ~]$ **instance network &**
4. [1] 19851
5. [student@servera ~]$ **instance interface &**
6. [2] 19857
7. [student@servera ~]$ **instance connection &**
8. [3] 19864
9. In the right terminal shell, verify that all three processes are appending content to the /home/student/instance_outfile file. Keep the tail command running to verify the output states in subsequent steps.[student@servera ~]$ **tail -f ~/instance_outfile**
10. network interface connection network interface connection network interface

16. Use signals to suspend the instance network process, and verify that the process is stopped.
    1. In the left terminal shell, stop the instance network process. Verify that the process state is Stopped.[student@servera ~]$ **kill -SIGSTOP %1**

    3. [student@servera ~]$ **jobs**

    5. [2] Running instance interface &
    6. [3]- Running instance connection &**Note**This guided exercise uses job numbers (%1, %2, and so on) to send signals, which is appropriate in this context because the processes are started in the same shell session and the job control features of Bash are available. If desired, you can also identify the parent process ID (PPID) by using the ps aj command, and send signals directly to the parent shell or individual process IDs (PIDs) instead. This approach is especially useful when scripting or working across multiple sessions.
    7. In the right terminal shell, view the tail command output. Verify that the word network is no longer appended to the ~/instance_outfile file....output omitted...

23. List the current running processes in all open terminal shells. Terminate the tail process that is running in the right terminal, and verify that the process is no longer running.
    1. In the left terminal shell, list all current running processes. Refine the search to view only tail lines.Note the PID of the tail command to use at a later step.[student@servera ~]$ **ps -ef | grep tail**
    2. student 4581 31358 0 10:02 pts/0 00:00:00 tail -f /home/student/instance_outfile
    3. student 4869 2252 0 10:33 pts/1 00:00:00 grep --color=auto tailThe output shows two processes: one to run the tail command (PID 4581) and one to run the grep command (PID 4869). The process with PID 4869 is listed because it contains the string tail, which matches the filtering of the ps -ef command (grep tail). The grep command exits immediately after the pipeline finishes, which leaves the tail process as the only process that matches the criteria.
    4. Still in the left terminal shell, terminate the tail process. Use the PID that you obtained in the previous step. The PID might vary in your environment.Verify that the process is no longer running.[student@servera ~]$ **kill -SIGTERM 4581**

    6. student 4874 2252 0 10:36 pts/1 00:00:00 grep --color=auto tailAlternatively, you can run the killall tail command. As confirmed in a previous step, only one tail process is running, which means that terminating all tail processes does not affect other processes or unintended users.

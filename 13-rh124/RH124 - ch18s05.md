# Configuring Hostnames and Name Resolution

## Objectives

- Configure a server's static hostname and its name resolution, and test the results.

## Updating the System Hostname

The fully qualified domain hostname (FQDN) uniquely identifies each server in the network. The hostname command displays or temporarily modifies the system's FQDN.\
In the following example, you temporarily change the host.example.com hostname to web1.example.com:

```
root@host:~# hostname
host.example.com
root@host:~# hostname web1.example.com
root@host:~#
```

```
hostname
```

```
web1.example.com
```

Using the hostname command results in a temporary hostname change. If you reboot the system, then the FQDN returns to its previous definition.\
To set a persistent hostname, it must be specified in the /etc/hostname file, which is read when the system starts. You can manually add the required hostname to the file, or you can use the hostnamectl command. The hostnamectl command offers a convenient way to both modify this file and to display the system's fully qualified hostname.\
You can use the hostnamectl hostname command to view the current hostname, or use the same command with an argument to update the hostname to the provided name. In the next example, you persistently change the host.example.com hostname to db1.example.com:

```
root@host:~# hostnamectl hostname
host.example.com
root@host:~# hostnamectl hostname db1.example.com
root@host:~# hostnamectl hostname
db1.example.com
```

You can verify that the /etc/hostname file is updated with the new hostname:

```
root@host:~# cat /etc/hostname
db1.example.com
```

## Note

In these examples, the prompt shows the previous hostname even after an update, because the shell uses the environment variables that were set when it first started. To see the new hostname reflected in your prompt, you can either open a new terminal session or manually update your shell's environment variables.\
In situations where the /etc/hostname file does not exist or it is empty, the system automatically sets a transient hostname based on a reverse DNS lookup on the IP address that is assigned to its network interface.

```
root@host:~# hostnamectl
   Static hostname: (unset)
Transient hostname: host.example.com
...output omitted...
```

## Important

In Red Hat Enterprise Linux 7 and later versions, the static hostname is stored in the /etc/hostname file. Red Hat Enterprise Linux 6 and earlier versions store the hostname as a variable in the /etc/sysconfig/network file.

## Configuring Name Resolution

A stub resolver is a lightweight DNS client that runs on your local machine. Its primary job is to receive DNS queries from applications and to forward those queries to a recursive DNS name server if the stub resolver cannot resolve the query. The order of name resolution is configured in the /etc/nsswitch.conf file. By default, the system attempts to resolve the query by first using the /etc/hosts file.

```
root@host:~# cat /etc/hosts
127.0.0.1       localhost localhost.localdomain localhost4 localhost4.localdomain4
::1             localhost localhost.localdomain localhost6 localhost6.localdomain6
172.25.254.254  classroom.example.com classroom
172.25.254.254  content.example.com content
```

If the /etc/hosts file does not contain a matching entry, then the stub resolver queries a DNS name server to look up the hostname. The /etc/resolv.conf file controls how this DNS query is performed:

- search : A list of domain names to append when short hostnames are looked up.
- nameserver : The IP address of a name server to query. Up to three name server directives can be given to provide backups if one name server is down.

```
root@host:~# cat /etc/resolv.conf
# Generated by NetworkManager
search example.com
nameserver 172.25.250.100
```

NetworkManager uses DNS settings stored in connection profiles to update the /etc/resolv.conf file. Use the nmcli command to modify connections:

```
root@host:~# nmcli con mod 'Wired connection 1' ipv4.dns 172.25.250.220
root@host:~#
```

By default, the nmcli con mod ID ipv4.dns IP command overwrites existing name server entries with the provided IP address. To add or remove a specific DNS server, prepend the ipv4.dns option with a plus (+) or minus (-) character, respectively.

```
root@host:~# nmcli con mod 'Wired connection 1' +ipv4.dns 172.25.254.254
root@host:~# nmcli con up 'Wired connection 1'
root@host:~# cat /etc/resolv.conf
# Generated by NetworkManager
search example.com
nameserver 172.25.250.220
nameserver 172.25.254.254
```

In the following example, the DNS server with an IPv6 address of 2001:4860:4860::8888 is added to the list of name servers stored in the static-ens4 profile:

```
root@host:~# nmcli con mod static-ens4 +ipv6.dns 2001:4860:4860::8888
```

On a dual-stack system, ensure that you list at least one reachable IPv4 name server and one IPv6 name server to maintain connectivity during issues with either protocol stack.

## Important

NetworkManager automatically rewrites the /etc/resolv.conf file on DHCP-enabled connections unless you configure the ignore-auto-dns yes setting in the connection profile by using the nmcli command.

```
root@host:~# nmcli con mod "static-ens3" ipv4.ignore-auto-dns yes
```

**Testing DNS Name Resolution**\
The host HOSTNAME command helps to diagnose DNS server connectivity by attempting to resolve the specified hostname.\

```
root@host:~# host servera.lab.example.com
servera.lab.example.com has address 172.25.250.10
root@host:~# host 172.25.250.10
10.250.25.172.in-addr.arpa domain name pointer servera.lab.example.com.
```

The dig command is a more powerful alternative to the basic host command for querying DNS servers. The dig command supports a wider range of options and provides more detailed output.

```
root@host:~# dig servera.lab.example.com

;; global options: +cmd
;; Got answer:
```

Neither the host nor the dig commands consider hostname entries in the /etc/hosts file. These are lookup tools that connect to DNS servers directly.\
You can use the getent hosts command to test hostname resolution by using standard C library calls, which follows the same procedure as other applications on your system. Keep in mind that the default configuration prioritizes checking the /etc/hosts file before resorting to a DNS server lookup.\

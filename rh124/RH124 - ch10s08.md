# Guided Exercise: Manage Local Group Accounts

Create, modify, and delete local group accounts.\
**Outcomes**

- Create and manage supplementary groups.
- Configure Sudo access for a group.\
  As the student user on the workstation machine, run the following lab command to prepare your environment for this exercise, and to ensure that all required resources are available.

```
student@workstation:~$ lab start users-group
```

**Instructions**

1. As the root user on the servera machine, create the operators and admin supplementary groups.
   1. As the student user on the workstation machine, log in to the servera machine as the student user. Switch to the root user. Use student as the password.student@workstation:~$ **ssh student@servera**
   2. ...output omitted...
   3. [student@servera ~]$ **sudo -i**
   4. [sudo] password for student: **student**
   5. [root@servera ~]#
   6. Create the operators supplementary group with a GID of 30000.[root@servera ~]# **groupadd -g 30000 operators**
   7. Create the admin supplementary group without specifying a GID.[root@servera ~]# **groupadd admin**
   8. Verify that both the operators and admin supplementary groups exist.[root@servera ~]# **tail /etc/group**
   9. ...output omitted...
   10. operators:x:30000:
   11. admin:x:30001:
2. Add the operator1, operator2, and operator3 users to the operators group, and verify the group membership.
   1. Add the operator1, operator2, and operator3 users to the operators group.[root@servera ~]# **usermod -aG operators operator1**
   2. [root@servera ~]# **usermod -aG operators operator2**
   3. [root@servera ~]# **usermod -aG operators operator3**
   4. Confirm that the users are in the group.[root@servera ~]# **id operator1**
   5. uid=1003(operator1) gid=1003(operator1) groups=1003(operator1),30000(operators)
   6. [root@servera ~]# **id operator2**
   7. uid=1004(operator2) gid=1004(operator2) groups=1004(operator2),30000(operators)
   8. [root@servera ~]# **id operator3**
   9. uid=1005(operator3) gid=1005(operator3) groups=1005(operator3),30000(operators)
3. Add the sysadmin1, sysadmin2, and sysadmin3 users to the admin group, and verify the group membership.
   1. Add the sysadmin1, sysadmin2, and sysadmin3 users to the admin group.[root@servera ~]# **usermod -aG admin sysadmin1**
   2. [root@servera ~]# **usermod -aG admin sysadmin2**
   3. [root@servera ~]# **usermod -aG admin sysadmin3**
   4. Confirm that the users are in the group.[root@servera ~]# **id sysadmin1**
   5. uid=1006(sysadmin1) gid=1006(sysadmin1) groups=1006(sysadmin1),30001(admin)
   6. [root@servera ~]# **id sysadmin2**
   7. uid=1007(sysadmin2) gid=1007(sysadmin2) groups=1007(sysadmin2),30001(admin)
   8. [root@servera ~]# **id sysadmin3**
   9. uid=1008(sysadmin3) gid=1008(sysadmin3) groups=1008(sysadmin3),30001(admin)
   10. Examine the /etc/group file to verify the supplementary group memberships.[root@servera ~]# **tail /etc/group**
   11. ...output omitted...
   12. operators:x:30000:operator1,operator2,operator3
   13. admin:x:30001:sysadmin1,sysadmin2,sysadmin3
4. Enable administrative rights for all members of the admin group. Verify that any member of the admin group can run administrative commands.
   1. Grant the admin group full administrative privileges by creating the /etc/sudoers.d/admin file with the appropriate permissions.The %admin ALL=(ALL) ALL string means that members of the admin group can run any command as any user, including the root user.[root@servera ~]# **echo "%admin ALL=(ALL) ALL" > /etc/sudoers.d/admin**
   2. Switch to the sysadmin1 user (a member of the admin group).[root@servera ~]# **su - sysadmin1**
   3. Without using Sudo, try to read the last entries of the /var/log/messages file.The command should fail because the sysadmin1 user does not have permission to read the file.[sysadmin1@servera ~]$ **tail /var/log/messages**
   4. tail: cannot open '/var/log/messages' for reading: Permission denied
   5. Use Sudo to read the last entries of the /var/log/messages file. Use redhat as the password for the sysadmin1 user.The command should succeed because the sysadmin1 user can use the Sudo privileges granted to the admin group.[sysadmin1@servera ~]$ **sudo tail /var/log/messages**
   6. [sudo] password for sysadmin1: **redhat**
   7. ...output omitted...

   9. May 18 04:59:40 servera systemd[1]: Starting systemd-hostnamed.service - Hostname Service...
   10. May 18 04:59:40 servera systemd[1]: Started systemd-hostnamed.service - Hostname Service.
5. Return to the workstation machine as the student user.[sysadmin1@servera ~]$ **exit**

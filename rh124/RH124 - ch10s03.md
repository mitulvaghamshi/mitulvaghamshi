## The Superuser

Most operating systems have a superuser that has all power over the system. In Red Hat Enterprise Linux, the superuser is the root user. This user has the power to override regular privileges on the file system, and you can use it to manage and administer the system. For tasks such as installing or removing software, and to manage system files and directories, users must escalate their privileges to the root user.\
Usually, only the root user can control most devices, but some exceptions apply. For example, regular users can control removable devices, such as USB devices. Thus, regular users can add and remove files and otherwise manage a removable device, but only the root user can manage hard drives by default.\
This unlimited privilege, however, comes with responsibility. The root user has unlimited power to damage the system: they can remove files and directories, remove user accounts, add back doors, and so on. If the root user account is compromised, then the system is in danger and you might lose administrative control. Red Hat encourages system administrators to always log in as a regular user, and to escalate privileges to root only when needed.\

## Important

In RHEL 10, the root account has no valid password by default, so you cannot directly log in as the root user with a password.\
The root account on Linux is similar to the local Administrator account on Microsoft Windows. In Linux, most system administrators log in to the system as an unprivileged user and use various tools to temporarily gain root privileges.

## Warning

Microsoft Windows users might be familiar with the practice of logging in as the local Administrator user to perform system administrator duties. Today, this practice is not recommended; users obtain privileges to perform administration by membership in the Administrators group. Similarly in RHEL, Red Hat recommends that system administrators never log in directly as root. Instead, system administrators log in as a regular user and use mechanisms to temporarily gain superuser privileges (su, sudo, or PolicyKit, for example).\
When logged in as root, the entire desktop environment unnecessarily runs with administrative privileges. A security vulnerability that might typically compromise only a regular user account can potentially compromise the entire system.

## Switching User Accounts

With the su command, users can switch to a different user account. If you run the su command from a regular user account with another user account as a parameter, then you must provide the password of the account to switch to. When the root user runs the su command, you do not need to enter the user's password.\
This example uses the su command from the user01 account to switch to the user02 account:

```
user01@host:~$ su - user02
Password: user02_password
user02@host:~$
```

If you omit the username, then the su or su - command attempts to switch to root by default.

```
user01@host:~$ su -
Password:
```

The su command starts an interactive non-login shell, but the su - command (with the dash option) starts an interactive login shell. The difference between the two commands is that the shell is initialized in slightly different ways when it starts, depending on whether it is a login shell or a non-login shell.

```
su -
```

Starts a new interactive login session as the user to whom you are switching, and uses the target user's environment settings.

```
su
```

Starts an interactive shell as the user to whom you are switching, but partially uses the original user's environment settings.\
Generally, administrators should run the su - command to get a shell with the target user's environment settings. This approach ensures that the resulting shell is initialized in the same way that it would be if that user logged in as usual. For more information, refer to the bash(1) man page.

## Running Commands with Sudo

In RHEL 10, the root account has no valid password by default. In other words, there is no password that allows a user to authenticate and to access the root account, either by attempting to log in directly as root or by attempting to use the su command.

## Important

The system administrator could set a password for the root account, which would allow you to become the root user with the su command if you know that password.\
For security reasons, system administrators commonly do not set a valid password for the root account. In that case, to get access to the root account, users must use a regular password to log in to a regular user account, and then use the sudo command to become the root user or to run commands as the root user.\
Unlike the su command, the sudo command typically requires users to enter their own password for authentication, not the password of the user account that they are trying to access. That is, users who use the sudo command to run commands as the root user do not need to know the root password. Instead, they use their own passwords to authenticate access.\

## Note

For security reasons, the sudo command modifies the shell environment it sets up before it runs commands or starts interactive sessions, based on settings in its configuration files. With the default configuration, the resulting environment is similar to the one you would get if you logged in as that user to start a new session.\
**Configuring Sudo**\
The /etc/sudoers file is the main configuration file for the sudo command. To avoid problems if multiple administrators try to edit the file at the same time, you can edit it only with the special visudo command. The visudo editor also validates the file, to ensure no syntax errors.\

For example, the following line from the /etc/sudoers file enables sudo access for wheel group members:

```
%wheel        ALL=(ALL:ALL)       ALL
```

- The %wheel string is the user or group that the rule applies to. The percent sign (%) before the wheel word specifies a group.
- The ALL=(ALL:ALL) command specifies that on any host with this file (the first ALL), users in the wheel group can run commands as any other user (the second ALL) and as any other group (the third ALL) on the system.
- The final ALL command specifies that users in the wheel group can run any command.\
  By default, the /etc/sudoers file also includes the contents of any files in the /etc/sudoers.d directory as part of the configuration file. With this hierarchy, you can add sudo access for a user by putting an appropriate file in that directory.
